# Project presentation

Keep the presentation of ECHOLIVITY SDD-3000 grounded in the software itself.

- The repository README shows a hardware-inspired concept render ([echolivity-sdd3000-concept.jpg](../echolivity-sdd3000-concept.jpg)). It must stay captioned as a concept, never presented as a product photo or as the device's interface.
- [ui_preview.png](../ui_preview.png) is generated by the build script (`tools/build_amxd.py`) as an approximate preview of the panel layout; it is not a capture from Live.
- Do not present generic rack-equipment imagery, simulated hardware panels or decorative artwork as product screenshots.
- Only add new interface images when captured from the current project build. Identify the build or release candidate where useful.
- Keep technical documentation clean and readable; prioritise controls, workflow, validation evidence and known limitations over decoration.
- The SDD-3000 is an independent software project inspired by a historical digital delay. Do not imply official Korg affiliation or hardware reproduction.
